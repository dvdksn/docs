## Design Context

### Users

Developers consuming Docker's official product documentation — anywhere from
first-time newcomers running their first container to enterprise platform
engineers wiring up Hardened Desktop, Build Cloud, or Compose specs. They
read at workstations during work, often in deep-focus scanning mode, and
frequently copy commands directly out of the page. The site spans 1,596
pages across product manuals, guides, CLI/API reference, and admin/billing.

Primary jobs to be done:
- Find specific reference info quickly (CLI flag, Compose key, API field).
- Follow a tutorial end-to-end and have it actually work.
- Scan a guide to understand a concept, then jump to the relevant reference.
- Copy a command without copying the `$` prefix.
- Ask Gordon (the embedded AI panel) when scanning fails.

### Brand Personality

Confident, precise, quietly playful. The aesthetic is already named in
`src/styles/theme.css`: **Infrastructure Modernism** — monochrome neutrals
with strategic Docker blue, hairline borders, flat surfaces, monospace
micro-labels, terminal-influenced precision crossed with Swiss design
clarity.

The "quietly playful" note is the one extension on top: substance and
restraint dominate, but small deliberate moments of character (an
easter-egg empty state, a microcopy line with a voice) are welcome.
Docker has whales and Gordon — own them sparingly, never as decoration
sprayed across the page.

### Aesthetic Direction

**Already locked in (do not change without explicit user direction):**

- **Fonts**: Roboto Flex (variable, body) + Roboto Mono (UI chrome, code).
  Self-hosted as woff2 in `public/fonts/`. These are deliberate project
  choices, not impeccable's font-selection step — do not swap them.
- **Brand color**: Docker Blue `#2560ff` (`--d-blue-500`). Used for
  active state, focus, and the one true link color. Never as a background
  fill, never as a gradient, never as decoration.
- **Surfaces**: Flat. Hairline borders (`--sl-color-hairline`) define
  structure. Box-shadow is reserved for true elevation (modals, popovers,
  the slide-out AI panel). No drop shadows on cards.
- **Type-as-signal**: Roboto Mono in uppercase + tracked spacing marks
  *UI chrome* — sidebar group labels, badges, callout titles, table
  headers. Roboto Flex carries all content. Don't let mono drift into
  decoration.

**Theme priority**: Dark mode is the primary surface — the developer
audience defaults there, and the GitHub-derived dark palette
(`#0d1117` / `#161b22` / `#21262d`) is what most readers see first. Tune
contrast, hierarchy, and accent strength against dark first; light mode
is an honored alternative that must hold up but doesn't lead.

**References to study (when stuck):**
- The current `theme.css` — it already names the aesthetic.
- Stripe Docs (for typographic restraint, not for SaaS hero patterns).
- Native man pages and well-loved CLI help output (for density).

**Anti-references — what the docs must NOT look like:**

- **Generic SaaS marketing**: gradient heroes, three identical feature
  cards in a row, neon purple-to-blue accents, glassmorphism. The "every
  YC startup" template is the most likely failure mode for splash pages.
- **Enterprise / IBM Carbon density**: gray-on-gray, navy header bars,
  dropdown-heavy chrome, compliance-poster aesthetic. Too corporate for
  the developer audience.
- **Mascot maximalism**: hand-drawn doodles, wrinkled-paper textures,
  the whale rendered three sizes large on every page. The personality
  is in the writing and small details, not the iconography.
- **AI-product clichés**: glassy purple-cyan gradients, "sparkle" icons
  everywhere, glowing borders on the Gordon panel just because it's AI.
  The AI panel must look like it belongs to *this* docs site, not to
  ChatGPT or Claude.

### Scope

Impeccable design work applies across three surfaces:
- **Marketing-style splash & landing pages** — section index pages,
  product splash pages, the home page (hero composition, CardGrids,
  bold-but-restrained layout).
- **Content page chrome & long-form reading** — typography, callouts,
  code blocks, tables, sidebar, in-page nav. The 95% of pages a reader
  actually reads.
- **App-like features** — Gordon AI panel, search, version switchers.
  Closer to product UI than to content; needs to feel native to the
  docs shell, not bolted on.

Reusable embedded components (SummaryBar, Version, CallToAction,
DesktopInstall, LabspaceLaunch) follow from these — they should feel
consistent with whichever surface they're embedded in.

### Design Principles

1. **Substance over decoration.** Every element earns its place. Nothing
   is there to "look designy" — if removing it doesn't damage the page,
   remove it.
2. **Hairlines, not shadows.** Flat surfaces with single-pixel borders
   define structure. Reach for `box-shadow` only for true elevation
   (modals, popovers, the slide-out AI panel).
3. **Monospace is a structural cue, not a vibe.** Roboto Mono signals UI
   chrome — sidebar group labels, badges, callout titles, table headers.
   Don't use it to make body content "feel technical."
4. **Tight, deliberate accent.** Docker blue is rare and load-bearing.
   Active state, focus ring, the one true link color. No gradients, no
   background fills, no neon. Its power comes from scarcity.
5. **Quiet character beats loud novelty.** One well-placed moment of
   personality (an easter-egg empty state, a microcopy line that has a
   voice) outperforms ten "delight" micro-animations. Earn the playful
   note; don't sprinkle it.
